# Fase 5: dashboard y verificación final

Dashboard con rango máximo de 367 días y agrupación por día, semana (lunes) o mes. Los KPI comparan el rango con el periodo inmediatamente anterior de igual duración. Hoy se compara con ayer y el mes actual con el mes anterior completo, explicitado en pantalla. Si la base anterior es cero se muestra «Sin base anterior» en vez de inventar un porcentaje.

Las cifras de importe y ticket excluyen cancelados mediante SalesCriteria. Se usa America/Guayaquil para límites y etiquetas; las agrupaciones SQL aplican UTC-5 para las fechas admitidas. Categorías y productos muestran bruto de líneas antes de descuento/envío; categorías se atribuyen según el catálogo actual. Métodos de pago muestran total del pedido, no dinero cobrado. El gráfico operativo de estados incluye cancelados y lo indica.

Gráficos SVG propios, locales y sin biblioteca adicional, con valores textuales accesibles. Alertas de stock, pedidos antiguos, pagos pendientes, reseñas, mensajes y cupones; enlaces a las pantallas correspondientes. Pedidos recientes filtrables con formulario CSRF y estados permitidos. Caché de 30 segundos por rango/agrupación/filtro; una escritura puede tardar hasta ese tiempo en reflejarse. La autorización de Admin se ejecuta antes de acceder a caché.

Consultas agrupadas en SQL para KPI, series, inventario, clientes, productos, categorías, métodos y estados; no se consulta por cada producto. Solo se agrupan en memoria las filas diarias ya agregadas (máximo 367). Los reportes del dashboard exportan KPI y series a CSV/XLSX neutralizando fórmulas.

Regresiones nuevas: límites del día local, exclusión de cancelados, comparación previa, ticket, suma de series/categorías/métodos, unidades de productos y autorización/exportación. La fixture nueva descubrió una causa raíz adicional: números importados reiniciaban el contador de pedidos. Los nuevos pedidos ahora usan BISU- más un identificador aleatorio de 24 caracteres hexadecimales, con índice único; conservan los números históricos y dejan de prometer consecutividad. Se añadió una regresión explícita con pedido importado. No son números de factura fiscal.

Resultado: build Release 0 errores/advertencias; 134/134 pruebas aprobadas, 0 omitidas (36 s del runner); TRX local audit/test-results/fase5.trx. Análisis NuGet transitivo sin paquetes vulnerables en los cinco proyectos. No se certifica ausencia de vulnerabilidades desconocidas. El primer intento falló por el generador de pedidos; se corrigió antes de guardar esta fase.

Pendientes externos: ejecutar workflow Linux en GitHub, configurar y probar SMTP, dominio/proxy/almacenamiento persistente y pagos reales. Pendientes técnicos explícitos: índice UserId sin estrechar datos existentes, reportes masivos por streaming, almacenamiento distribuido de carrito/cola y auditoría transaccional de diferencias. No hubo pruebas de carga ni despliegue productivo.
